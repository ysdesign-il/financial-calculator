# Financial Calculator Enhancements (starter integration) This package contains a drop-in JavaScript enhancement module for the existing financial-calculator website. ## Features in this module - Copy result text / calculator summary. - Duplicate current form fields into a separate editable panel without overwriting the original. - Save a calculator snapshot (inputs and detected result text) into a local saved folder. - Load saved values into a matching active calculator form. - Export saved snapshots as JSON. - Browser print dialog for PDF (`Print -> Save as PDF` where supported). - Local preferences UI for automatic/manual source selection and custom market symbols. - Four additional calculators: loan payment, compound growth, inflation/purchasing power, and savings goal. ## Important limitations 1. This is an integration module, not a verified modification of the live GitHub repository. The GitHub connector currently rejects write operations with HTTP 403. 2. Saved data is stored in `localStorage` on the current browser/device only. It does not sync across users/devices and is not a secure cloud vault. 3. Source selection stores user preferences and emits `fcx:source-preferences-changed`. It does not create market-data provider integrations by itself. To replace CNBC, connect a licensed/reliable data provider and treat the event as a trigger for a real adapter. 4. PDF export opens the native print dialog; the user chooses “Save as PDF”. 5. The module uses DOM heuristics to find the active form and result region. Integrate against the app's actual calculator components and IDs before deploying to production. 6. Financial formulas are illustrative. Validate edge cases, fees, payment timing, taxes, compounding conventions, and currency assumptions with tests before using for decisions. ## Installation Add `enhancements.js` to the repository and include it near the end of `index.html`, before ``: ```html ``` Test on a staging branch first. Do not overwrite the live single-file app until the integration has been reviewed. ## Source adapter integration Listen for the preference event and route it to your real data-source layer: ```js document.addEventListener("fcx:source-preferences-changed", (event) => { const preferences = event.detail; // TODO: connect preferences to the app's source-selection / quote-fetching code. // The app should fall back safely, show source + updatedAt, and disclose delays. }); ``` ## Suggested next production steps - Integrate the saved/duplicate/copy actions with the app's actual calculator state model, rather than DOM heuristics. - Add unit tests for financial calculations and regression tests for existing calculators. - Add provider adapters with explicit licenses and rate-limit handling. - If saved data should sync across devices, implement authenticated backend storage and access controls. ## Developer admin and protected code editor This project now includes a password-protected developer admin panel that can open the repository files, edit them inside the browser, and save them back to GitHub using the repository API. ### Quick setup 1. Copy `.env.example` to `.env`. 2. Fill in values: - `ADMIN_PASSWORD` - `SESSION_SECRET` - `GITHUB_TOKEN` - `GITHUB_OWNER` - `GITHUB_REPO` - `GITHUB_BRANCH` 3. Install dependencies: ```bash npm install ``` 4. Start the server: ```bash npm start ``` 5. Open: ```text http://localhost:3000/admin ``` ### Admin login Use the configured `ADMIN_PASSWORD` to sign in. ### What the admin does - List repository files - Open a file in the browser editor - Save edits directly to GitHub - Optionally request AI help via OpenAI using the same editor context - Keep the website in sync by updating the repo contents automatically ### Important security notes - Never expose `GITHUB_TOKEN`, `OPENAI_API_KEY`, or the admin password in frontend code. - Keep the admin behind HTTPS in production. - Use a strong `SESSION_SECRET`. - Restrict the GitHub token's permissions to the minimum required. ### Optional AI feature If `OPENAI_API_KEY` is set, the admin includes a prompt-based helper for code generation and code transformation. ### Production recommendation - Put the server behind a real deployment platform such as Render, Vercel, Railway, or a VPS. - Use a strong password or a proper auth layer if multiple developers will use it. - Prefer a private branch or PR flow for production-safe updates.
